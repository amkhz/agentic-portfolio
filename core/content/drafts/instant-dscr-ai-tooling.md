## Where the AI tooling actually fits

Two different jobs, and conflating them is the common mistake.

**For building.** The agent is how I work in a production monorepo at engineering
standard. It reads unfamiliar code with me, holds a captured API response next to a
rendered screen, writes the tests I would have skipped, and enforces the standards the
repo declares. I still make the calls. The 100× error was found by *looking*; the agent
made looking cheap enough that I did it at all. Plan documents are the working surface —
the two behind this feature run about 500 lines each and carry the reversals, not just
the conclusions.

**For design.** Every option above was drawn as a real screen with real numbers, fast
enough that six directions cost less than one used to. That speed changes what you
explore. Options A through D were not strawmen; they were live enough to be argued with,
which is why the winning idea came from noticing something true about the *data* rather
than from picking the prettiest board.

The thing I would want understood: none of this replaced design judgment. It removed the
tax on exercising it. The decision to keep the interest-only pair cost nothing to
implement and took the longest to make.
